# spec-humanize — story.md 人话改稿

spec-story-design 产出 story.md 后、spec-point-verify 判读前执行。职责单一：把 AI 味改成人话。

## 为什么单独一步

生成子代理注意力在技术内容正确性上，顾不上写作风格。改稿子代理 100% 注意力在人话上，效果稳定。和 spec-point-verify 一样的分离原则——生成和审查各管各的。

## 改什么，不改什么

**改**（正文散文段落）：
- 功能描述段落
- 澄清问题/结论文字
- 边界与约束段落
- 需关注事项条目
- 资产缺口描述
- 方案选型约束（如有）
- 表格内的文字内容（功能点描述、变更说明等）

**不改**：
- mermaid 代码块（图内文字不改）
- 推导表的判定列（待判读/通过/需修订/打回设计）
- 文件路径、代码路径、包名、函数名
- 资产文档引用路径（docs/0-xxx.md）
- 表格结构（不增删行列）
- 编号（Q1/Q2、变更1/变更2 等）

## 人话规则

### 第一条：写人话，用人能理解的表达模型

文档首先要是人话——不是技术术语堆砌，不是模板套话，是人在跟人解释事情。

表达模型：直接说做了什么决定、为什么这么选，不套固定句式。比如：
- 不要写"采用覆写式幂等去重"→ 写"导入时跳过重复文件，还是覆盖旧数据重新导入"
- 不要写"实现 per-alarm 抑制阈值机制"→ 写"不同告警用不同抑制周期，按告警 ID 查周期表"
- 不要写"引入 sync.RWMutex 读写锁隔离"→ 写"导入写时导出读不阻塞，用读写锁隔离"

人做决策时凭字面意思选，选项描述必须让人选了之后得到的确实是想要的结果。待选方案直接说清各自做什么、有什么区别。

### 绝对禁令（必须清零）

1. **阿拉伯数字不用中文**：300011 不是"三千零十一"，500000 不是"五十万"，3 点不是"三点"。技术文档里的告警 ID、行数上限、时间点一律阿拉伯数字。

2. **禁翻案腔**：翻案腔指先立一个读者并没有的误解，再推翻它给下文抬价。禁的是修辞动作，不是字面。换一套字继续做同一个动作，仍然算命中。已知外衣：

| 外衣 | 例子 |
| --- | --- |
| 字面翻案 | 不是A，而是B。并非A，而是B。不在于A，而在于B |
| 省字变形 | 不是A，是B。不是A，B才是 |
| 跨句变形 | 不是A。而是B。表面上是A。其实是B |
| 换字变形 | 与其说A，倒不如讲B。与其说A，毋宁说B |
| 以为体 | 你以为A，其实B。我一直以为A，后来才发现B。回头才发现 |
| 让转体 | 看似A，实则B。大家都说A，可真相是B。答案恰恰相反 |
| 抬价体 | A不重要，重要的是B。真正值钱的从来都与A无关 |

判断直接从正面下，先给判断，再给依据。

3. **禁破折号**：不写 `——`、`—` 和 `–`。用逗号或句号代替。

4. **禁提示性冒号**：冒号只允许两种用法——引出人物直接原话、代码/机器字段（网址、路径、配置键、JSON 字段）。以下冒号全部禁止："一句话总结：""核心是：""关键是：""重点是：""功能描述：""方案选型约束：""变更类型取值："等提示性冒号。标签后用空格或句号代替。

5. **禁模型路标**：不写"更微妙的是""还有一层""只说对了一半""值得注意的是""需要指出的是""从某种意义上说""说到底""说白了""说穿了""先说结论"。文字确实在说楼层、数量等本义时不受影响。

6. **禁商业黑话（绝对禁词）**：赋能、抓手、商业闭环、价值闭环、能力沉淀、拉通、底层逻辑、顶层设计、认知跃迁、价值释放、能力建设、降本增效、内容矩阵、全链路、组合拳、打开想象空间、结构性机会、关键命题、深层逻辑、技术底座、公共底座、技术主权、单点风险、主脊柱、材料锚点、认知增量、迭代闭环。改成人、动作、钱、时间与后果。

   语境检查词（本义使用时保留，抬价时改写）：沉淀、颗粒度、对齐、协同、链路、生态位、心智、范式、方法论、核心变量、打法、想象空间、闭环、不丢。

7. **禁动词名词化**："完成了对流程的优化"→"把流程改顺了"，"实现了效率的提升"→"快了多少"，"进行了校验"→"校验了"。搜索"进行了""实现了""完成了对""起到了……作用""具有……意义"，还原成直接动词。

8. **禁三项以上同构排比**：同一个引导词或同一个句型连排三次以上，留两项，第三项换说法或删掉。

9. **禁给抽象名词配具体动词写抒情**：时间不会保管细节，焦虑不会显出形状，岁月不会磨平什么。文章真的在写具体事物时不受影响。

10. **禁"无"解释**：如果某节内容是"无新增"后面跟一段解释为什么无，改为"无。"。不解释为什么没有。

### 风格规则

11. **短句带主语**：超长单句（超过 50 字）拆成短句，主语放前面。先让主语和动作出现，再往后接时间、原因、条件和例子。长句可以有，读者要尽早知道谁做了什么。"在文件服务器通知白名单文件变更时，主实例下载 CSV 文件并解析为"→"FileServer 通知文件变更后，主实例下载 CSV。解析时校验"。

12. **删重复**：同一信息出现多次的，保留信息最丰富的一处，其余删除。

13. **语气带判断**："需关注"→"注意"，"需确认"→"上线前确认"，"建议在"→"生成代码前先补"。加因果、加后果、用祈使句。

14. **澄清自然化**：澄清选项直接说清各自做什么、有什么区别，禁纯技术术语让人凭字面猜，不套固定句式。

15. **"不需要"精简**：推导表里"不需要（CSV 解析为语言基础能力）"→"不需要（语言基础）"，统一简短。

16. **段落有高低差**：连续几段长度接近，检查是不是每段都按同一模具完成。普通地方用普通句子结束，不要每段都用短判断收尾。

## 工作流程

### 第 1 步：读取文档

读取目标 story.md 全文。识别正文段落（改）和结构化内容（不改）的边界。

### 第 2 步：逐段改写

按人话规则逐段检查改写：
- 扫描中文数字 → 改阿拉伯数字
- 扫描翻案腔（按动作查不只按字面查）→ 改正面陈述
- 扫描破折号 → 改逗号/句号
- 扫描提示性冒号 → 改空格/句号（技术冒号保留）
- 扫描模型路标 → 删除或改写
- 扫描商业黑话 → 改人话
- 扫描动词名词化 → 改直接动词
- 扫描超长句 → 拆短句带主语
- 扫描"无——解释" → 改"无。"
- 扫描重复信息 → 删冗余
- 扫描"需关注/需确认/建议在" → 改祈使句
- 扫描澄清选项 → 改为直接说清做什么、有什么区别，去掉固定句式

### 第 3 步：跑 check_prose.py

脚本与本 SKILL.md 同目录（即 skill 的 base directory 下，如 `D:\Code\SBG\specgo\skills\spec-humanize\check_prose.py`）。执行命令：

```bash
# Windows PowerShell 需设置 UTF-8 编码避免中文输出乱码
$env:PYTHONIOENCODING="utf-8"; python "<skill_base_dir>/check_prose.py" "<文档路径>"

# Linux/Mac
python "<skill_base_dir>/check_prose.py" "<文档路径>"
```

**skill_base_dir 查找方式**：用 Glob 搜索 `**/spec-humanize/check_prose.py` 定位脚本绝对路径。

脚本会屏蔽代码块、URL、frontmatter、行内代码，只检查正文散文。

- **failures 必须清零**：翻案句、破折号、硬禁词、模型路标等 failure 项必须修复后重跑，迭代到 0。
- **warnings 逐条判断**：冒号 warning 逐条看——技术引用冒号（路径/配置键/JSON）保留并注明理由，提示句冒号必须改。其他 warning 按情况处理。
- **脚本执行失败的降级**：跑不了脚本时手动按人话规则逐条检查，不能跳过。

### 第 4 步：覆盖写回

改稿完成、check_prose.py failures 清零后，覆盖写回原文件。

## 红线

| 想法 | 现实 |
|------|------|
| "表格也一起改" | 只改正文文字，不动表格结构和判定列 |
| "mermaid 图里的中文数字也改" | mermaid 代码块不改，图内文字保持原样 |
| "check_prose.py 报了 warning 就算没过" | warning 逐条判断，技术冒号可保留；只有 failure 必须清零 |
| "改稿顺手把推导表判定填了" | 只改风格不改内容，判定列归 spec-point-verify |
| "check_prose.py 跑不了就跳过" | 脚本是确定性门禁，跑不了就手动按规则逐条检查，不能跳过 |
| "禁词清单自己加几个" | 禁词清单固定，不自行增加未写明的硬禁词 |

## 与其它 skill 的关系

- **spec-story-design**：前置，产出 story.md。spec-humanize 不改 story 的技术内容，只改写作风格。
- **spec-point-verify**：后继，spec-humanize 改完后人话风格已定，spec-point-verify 专注判读推导链。
- **specgo**：主流程在 spec-story-design 后、spec-point-verify 前调用 spec-humanize。

## 单独触发模式

已有 story.md 时可脱离 specgo 单独触发：输入 = 文档路径；产出 = 覆盖写回同一份文档；流程同第 1-4 步。
